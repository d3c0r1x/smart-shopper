# Безопасность — Smart Shopper

Документ фиксирует меры безопасности, реализованные в проекте (ТЗ §4), и что
проверено на момент написания. Цель — сделать утверждения проверяемыми:
каждая мера либо реализована в коде, либо явно отмечена как нереализованная
с ограничением риска.

## Управление секретами

- Секреты читаются только из переменных окружения / `.env` (`config.py`).
  В репозитории хранится только `.env.example` с пустыми значениями.
- Корневой `.gitignore` исключает `.env` из трекинга. Проверка
  `git grep` по шаблонам ключей (`sk-`, `AIza`, Telegram-токены, приватные
  ключи) по отслеживаемым файлам — **чисто** (проверено 2026-08).
- `run_bot12.cmd` читает ключи из корневого `.env` и подставляет их в
  окружение запускаемого процесса — значения не пишутся в файлы проекта.

## Защита от инъекций

- SQL: все запросы к SQLite параметризованы через `?` (плейсхолдеры
  `aiosqlite`). Единственное место с интерполяцией — `storage/db.py`,
  `stats()`: имя таблицы берётся из фиксированного кортежа
  `("sessions", "favorites", "cache")`, ввод пользователя туда не попадает.
- HTML в Telegram-сообщениях: пользовательский контент и тексты отзывов
  экранируются (`html.escape`) перед отправкой с `parse_mode=HTML`.
- LLM (ТЗ §4): ввод пользователя санитизируется до попадания в промпт —
  `llm/guardrails.py` (лимит длины `PROMPT_MAX_CHARS`, удаление control-
  символов); внешний контент (отзывы, названия товаров) — `review/`
  и `matcher/` обрезают текст до лимита и экранируют.
- Управляющий контент извне (промпт-инъекции через карточки/отзывы):
  внешний текст вставляется в промпт как **данные**, ограничен по длине;
  структурированные ответы LLM валидируются Pydantic-схемами
  (`llm/schemas.py`) — невалидный ответ отбрасывается, а не исполняется.

## Rate limiting и этичный парсинг (ТЗ §4)

- Адаптеры маркетплейсов используют публичные web-эндпоинты с вежливой
  паузой между запросами (`POLITE_DELAY`) и кэшем результатов в SQLite
  (`cache`): повторный поиск не долбит сайты.
- Таймауты на необязательные обогащения (отзывы, карточка) — при
  антибот-блокировке выдача возвращается с тем, что реально найдено,
  без подмены демо-данными (принцип grounding).
- **robots.txt** — реализовано (`adapters/robots.py`): кэширующий
  парсер с longest-match, fail-open по стандарту RFC 9309 (нет файла =
  разрешено), отключение — `SHOPPER_RESPECT_ROBOTS=0`;
- **Экспоненциальный backoff** на 429/5xx — реализовано
  (`adapters/base.py`, `_backoff`: 0.5→10 c);
- Прокси-ротация — реализована для подписки Happ (`core/proxy_pool`),
  остальные прокси-источники — на усмотрение при масштабировании.

## Изоляция окружения (ТЗ §4)

Песочница **реализована** (`Dockerfile` + `.dockerignore`):

- бот запускается в контейнере `python:3.12-slim` под **не-root**
  пользователем (`USER shopper`, принцип наименьших привилегий);
- **секреты не попадают в образ**: `.env` и `.env.*` исключены через
  `.dockerignore`, ключи передаются только при запуске (`--env-file` /
  `-e`), `.env.example` в образе не содержит значений;
- сеть: контейнер на Docker bridge — **без доступа к хостовой сети**,
  наружу открыт только HTTP-API 8081; egress к маркетплейсам и LLM-API
  разрешён (иначе бот не сможет работать), для строгого allowlist
  доменов — внешний файрвол/прокси поверх;
- healthcheck через `/health` (урllib вместо curl — slim-образ);
- сборка/запуск: `docker build -t smart-shopper .` и
  `docker run --rm -d -p 8081:8081 --env-file ../.env smart-shopper`.

Ограничения (честно): Docker на этой машине разработчика не установлен,
поэтому образ не собирался локально — синтаксис проверен, сборка
предполагает любой Docker-хост. gVisor не применим (Windows-хост без
containerd); при выделении браузерных каналов (Playwright + xray-пул)
нужен отдельный образ с браузером — зафиксировано в Dockerfile.

## Остаточные риски (честный список)

1. Бот в реальном режиме ходит на сайты маркетплейсов по их внутренним
   JSON-эндпоинтам. При блокировке IP антиботом поиск честно возвращает
   пустой результат — это не утечка, но и не гарантия доступности.
2. Публичный HTTP-API (порт 8081) защищён проверкой подписи Telegram
   initData; в режиме разработки возможен `SHOPPER_API_ALLOW_ANON=1`.
   Не включать анонимный режим на публичном хостинге.
3. Локальная LLM (Ollama) слушает на loopback — не открывать порт 11434
   наружу без аутентификации.
