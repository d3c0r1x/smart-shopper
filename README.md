# Smart Shopper — ИИ-ассистент покупок: Ozon · Яндекс Маркет · Wildberries

«ChatGPT для маркетплейсов»: вы общаетесь с ассистентом свободным текстом или
фотографией, а он отвечает рекомендациями, которые опираются **только на
реальные данные маркетплейсов** — карточки, цены, отзывы на Ozon,
Яндекс Маркете и Wildberries — и никогда не
выдумывает товары сам (принцип grounding).

Один backend — два интерфейса: **Telegram-бот** (сообщения с inline-кнопками)
и **Telegram Mini App** (React, полный экранный интерфейс). Состояние сессии
общее: уточнения «а подешевле», «только чёрные» применяются к прошлому поиску,
а не начинают его заново.

## 🕹 Демо

- **Telegram-бот**: `@dfs12f_bot` (общий демо-токен портфолио — одновременно
  может поллить только один проект). Запуск локально — `run_bot12.cmd`.
- **Mini App**: `cd miniapp && npm install && npm run dev` →
  `http://localhost:5173` (в браузере работает демо-режим на встроенном каталоге;
  в Telegram — через web_app-кнопку после развёртывания на HTTPS).
- Без ключа OpenRouter бот работает в демо-режиме: LLM-слой заменён
  детерминированным mock-провайдером с теми же JSON-схемами.

## Возможности

- **🔎 Умный поиск** — свободный текст → извлечение требований («до 1200 ₽»,
  «чёрный», «пространство для ресниц») → поиск на обеих площадках →
  **Review Intelligence**: каждое требование проверяется по отзывам
  (✅ подтверждено / ❌ опровергнуто / ⚠️ нет данных) с цитатами;
- **📸 Найти по фото** — фото → vision-модель (структурное описание) → поиск
  похожих → ранжирование по совпадению признаков;
- **⚖️ Сравнение цен** — тот же товар на Ozon, Яндексе и Wildberries
  (EAN → нечёткое название → LLM-арбитр): «Ozon: 990 ₽ · YM: 1 050 ₽ ·
  WB: 780 ₽ — выгоднее на WB на 26%»;
- **📝 Кликабельные отзывы** — кнопки «Отзыв 1…5», «Ещё»: отдельное сообщение
  с текстом, звёздами, автором, датой, пометкой «куплен на маркетплейсе»;
- **⭐ Избранное**, **⚙️ Настройки** (профиль моделей fast/quality, индикатор
  дневного бюджета, очистка контекста), **/diag** — диагностика доступа;
- **Память диалога** — сжатое состояние сессии в БД; уточнения применяются
  к прошлому поиску;
- **Честные ошибки** — при исчерпании дневного лимита бот говорит прямо с
  цифрами из документации OpenRouter;
- **HTTP-API** для Mini App (одни сессии с чатом): /api/search, /api/reviews,
  /api/compare, /api/budget — аутентификация по подписи Telegram initData.

## Сценарии

### Сценарий 1. «Увидел кроссовки в магазине — сфотографировал»
1. Пользователь нажимает «📸 Найти по фото» и отправляет фото;
2. Vision-модель возвращает строго JSON: категория, пол, цвет, материал,
   детали, 2–3 поисковых запроса на русском;
3. Адаптеры ищут на Ozon и Яндекс Маркете (до 20–30 кандидатов);
4. LLM-ранжирование по совпадению признаков;
5. Результат — 1–3 карточки с кнопками: `📝 Отзывы (N)` · `⚖️ Ozon vs YM` ·
   `⭐ Избранное` · `🔁 Ещё похожие` · `🛒 Открыть`.

### Сценарий 2. «Найди чёрную маску для сна с пространством для ресниц»
1. LLM извлекает ограничения в JSON (категория, цвет, обязательные требования);
2. Поиск → формальный префильтр (цвет/цена) → топ-кандидаты по «массе отзывов ×
   рейтинг»;
3. **Review Intelligence**: для каждого кандидата читается пул отзывов, и
   длинноконтекстная модель проверяет каждое требование: подтверждено /
   опровергнуто / нет данных + дословные цитаты;
4. Товары с подтверждёнными требованиями поднимаются наверх, опровергнутые
   опускаются; финал — 1–3 варианта с блоком «Ваш запрос: ✅ чёрный · ✅ 3D».

## Архитектура

```
bot.py                # Telegram-бот: команды, карточки, кликабельные отзывы
config.py             # настройки через переменные окружения (все секреты — .env)
models.py             # единые pydantic-модели (Product, Review, SessionState…)
core/
  orchestrator.py     # «мозг»: agent-loop, сценарии 1 и 2, память сессии
llm/
  gateway.py          # реестр :free-моделей, fallback-цепочки, бюджет, троттлинг
  providers.py        # OpenRouter (openai SDK) + детерминированный mock
  prompts.py          # системные промпты с правилом grounding
  schemas.py          # строгие JSON-схемы ответов (pydantic)
adapters/
  base.py             # контракт + HTTP-транспорты (httpx / curl_cffi), retry
  ozon.py             # канал 1: composer-api Ozon (web+mobile) + отзывы
  ozon_browser.py     # канал 1 (рабочий): Ozon через браузер+прокси,
                      #   ожидание решения Antibot Challenge, парсинг DOM
  yandex.py           # канал 1: JSON-эндпоинты SPA + fallback JSON-LD
  capture.py          # загрузка зафиксированных эндпоинтов (captured/*.json)
tools/capture_endpoints.py  # фиксация JSON-эндпоинтов (DevTools-процедура)
  yandex.py           # web-версия Яндекс Маркета (JSON-LD, честный статус)
  yandex_browser.py   # канал 1 (рабочий): Яндекс через браузер+прокси,
                      #   SSR/DOM-выдача с реальными ценами и ссылками
  wb_browser.py       # канал 1: Wildberries через браузер+прокси
                      #   (DOM-карточки: названия, цены, ссылки на карточки)
  demo.py             # демо-каталог: кроссовки и маски для сна с отзывами
review/
  intelligence.py     # анализ отзывов против требований + кэш (TTL 24 ч)
vision/
  service.py          # фото → data URI → vision-модель
matcher/
  matcher.py          # EAN → нечёткое название (RapidFuzz/difflib) → LLM-арбитр
web.py                # HTTP-API для Mini App (initData-валидация HMAC-SHA256)
storage/
  db.py               # SQLite (aiosqlite): сессии, кэш, избранное, бюджет LLM
miniapp/              # Telegram Mini App: React + Vite + @telegram-apps/sdk
tests/                # 39 тестов: адаптеры, gateway, бюджет, оркестратор,
                      # review, matcher + интеграционные через настоящий Dispatcher
```

**Поток одного хода диалога:** вход (чат или Mini App) → оркестратор →
план действий от LLM (инструменты: поиск, отзывы, сравнение) → исполнение
адаптерами → возврат фактов модели → финальный ответ и карточки → рендер.

**LLM Gateway (провайдеры: Mistral + OpenRouter :free-модели):**
- **Mistral** — текст-задачи (извлечение требований, анализ отзывов,
  ранжирование, арбитр, свободный чат): `mistral-small-latest` (быстро),
  `mistral-large-latest` / `mistral-medium-latest` (качественно). Ключ —
  `MISTRAL_API_KEY` (или `MISTRAL_KEY` в корневом `.env`);
- **OpenRouter** — vision (поиск по фото) и запасной канал для текста:
  цепочки `:free`-моделей с роутером `openrouter/free` в конце
  (бесплатные модели регулярно снимаются с публикации — хардкодить одну
  запрещено);
- роутинг цепочек по префиксу модели (`mistral:…` / `openrouter:…`): если
  ключа провайдера нет — его модели пропускаются, цепочка идёт дальше;
- дневной бюджет: 50 запросов/день, после разового пополнения от $10 —
  1000/день; троттлинг 20 запросов/мин (лимиты из документации OpenRouter);
- ответ модели валидируется pydantic-схемой; при провале — следующая модель
  в цепочке, в самом конце — честный фолбэк на mock (бот не падает);
- без ключей бюджет не тратится (mock-вызовы бесплатны).

## Публичные API маркетплейсов (канал 1 + честный статус)

### Канал 1: JSON-эндпоинты самих сайтов (SPA)

Сайты Ozon и Яндекс Маркета — SPA: браузер при поиске ходит не за HTML, а за
JSON-ответами внутренних API. Адаптеры используют их как основной канал
(`adapters/ozon.py`, `adapters/yandex.py`):

- **Ozon**: `composer-api.bx/page/json/v2` — web (`www.ozon.ru`) и mobile
  (`api.ozon.ru`, тот же формат, менее защищён). Ответ — `widgetStates` с
  JSON-строками; парсер рекурсивно находит товары и отзывы.
- **Яндекс Маркет**: JSON-эндпоинты SPA (`market.yandex.ru/api/...`) + fallback
  на web-версию с JSON-LD (`schema.org/Product`).

**Точные заголовки и cookies применяются 1-в-1 из реального браузерного
запроса — ничего не придумывается.** Процедура фиксации (аналог DevTools →
Network → Fetch/XHR, автоматизированный):

```bash
python tools/capture_endpoints.py --market ozon  --query "маска для сна"
python tools/capture_endpoints.py --market yandex --query "маска для сна"
# при необходимости: --proxy http://user:pass@host:port
```

Инструмент открывает сайт в настоящем браузере (Playwright + системный
Chrome), выполняет поиск/карточку/прокрутку отзывов и сохраняет URL, точные
заголовки и cookies каждого JSON-эндпоинта в `captured/{market}.json`.
Адаптеры автоматически используют этот файл; без него — документированные
семейства composer-api + cookie-бутстрап через главную страницу (сессия
сохраняет регион/сессионные куки, как браузер).

### Пул прокси подписки Happ — все серверы в деле (проверено живьём)

Подписка Happ — это ~300 vless-серверов (63 уникальных хоста, разные страны),
каждый со своим выходным IP. `proxy_pool.py` поднимает xray-инстансы
(из установки Happ) на локальных socks-портах 10811+ и ротирует их:
площадка блокирует один IP — поиск уходит через следующий.

- `SHOPPER_SUBSCRIPTION_URL` в корневом `.env` — URL подписки (из логов Happ);
  `tools/happ_proxy.py update` кэширует список серверов в `happ_servers.json`
  (в .gitignore — внутри UUID и ключи reality);
- `SHOPPER_PROXY_POOL=1` (по умолчанию) + `SHOPPER_POOL_SIZE=6` → при старте
  бот поднимает пул: `python tools/happ_proxy.py up 6` (health-check отсекает
  мёртвые серверы);
- каждый браузерный адаптер (`ozon_browser.py`, `yandex_browser.py`,
  `wb_browser.py`) при пустом результате пробует следующий прокси (до 3 IP);
- без пула — фиксированный `SHOPPER_PROXY`; без обоих — адаптеры честно
  работают напрямую.

**Результат живых прогонов через пул:** Ozon — реальные товары за ~5 с
(челлендж решается на чистом IP без ожидания), Яндекс и WB — реальная выдача
с ценами и ссылками на карточки. Демо-каталог в реальном режиме **не
используется**: пустой результат (блок всех IP) остаётся пустым, без подмены
на выдуманные товары.

**Важная деталь Ozon:** адаптеру нельзя задавать init-скрипт
`navigator.webdriver=undefined` — Ozon детектирует подмену и не решает
Antibot Challenge (проверено: с init-скриптом челлендж не решается, без него —
за ~5 с).

### Честный статус (антибот)

- Пустые результаты поиска не кэшируются — неудачный поиск не «замораживает»
  площадку до конца TTL (поиск в `core/orchestrator.py`).
- Демо-каталог (`adapters/demo.py`) — только при явном `SHOPPER_DEMO_MODE=1`;
  в реальном режиме подмена на выдуманные товары не происходит никогда.
- Официальные API — Ozon Seller API и Яндекс Partner API — это API продавца
  (свои товары, заказы); поиска по чужому каталогу в них нет.
- Решение: **прокси (`SHOPPER_PROXY`) с чистым IP** — браузерный канал для
  всех трёх площадок; **фиксация эндпоинтов** (`tools/capture_endpoints.py`);
  демо-режим (`SHOPPER_DEMO_MODE=1`) — встроенный каталог с реалистичными
  товарами и
  отзывами, все сценарии проверяемы оффлайн.

## Mini App

React + Vite + официальный `@telegram-apps/sdk`. Экраны: «Главная/Чат»,
«Результаты», «Карточка товара», «Отзывы» (bottom-sheet), «Сравнение цен»,
«Избранное» (localStorage), «Настройки» (бюджет LLM). Тема (светлая/тёмная)
наследуется из `themeParams` Telegram; вне Telegram — демо-тема.

```bash
cd miniapp
npm install
npm run dev        # локально: http://localhost:5173 (демо-режим)
npm run build      # production-сборка в miniapp/dist
```

Для подключения к бэкенду задайте при сборке `VITE_API_URL` (ожидаемые
эндпоинты: `/api/search`, `/api/reviews`, `/api/compare`, `/api/budget` —
контракт описан в `miniapp/src/api.ts`).

**Развёрнутая версия:** https://d3c0r1x.github.io/smart-shopper/
(GitHub Pages, ветка `gh-pages` — `index.html` + `assets/` из сборки).
В Telegram Mini App открывается web_app-кнопкой: кнопка **«🛍 Mini App»**
в постоянном меню бота и кнопка у поля ввода (`setChatMenuButton`,
устанавливается автоматически при старте бота). URL настраивается
переменной `SHOPPER_MINIAPP_URL` (по умолчанию — Pages-URL).

Для подключения к бэкенду задайте при сборке `VITE_API_URL` (ожидаемые
эндпоинты: `/api/search`, `/api/reviews`, `/api/compare`, `/api/budget` —
контракт описан в `miniapp/src/api.ts`).

## HTTP-API для Mini App

Запускается вместе с ботом (один backend, два рендерера):
`http://127.0.0.1:8081` (порт — `SHOPPER_API_PORT`).

**Автономный режим** (только API, без поллинга бота — для публичного
развёртывания):

```bash
python web.py          # http://0.0.0.0:8081, CORS включён
```

CORS-заголовки (`Access-Control-Allow-Origin: *`) разрешают браузерному
Mini App с другого домена (GitHub Pages) обращаться к API; авторизация —
через Telegram initData или `X-API-Token`. Публичный HTTPS-доступ можно
дать туннелем без регистрации (пример для демо):

```bash
cloudflared tunnel --url http://127.0.0.1:8081
# → https://<random>.trycloudflare.com
VITE_API_URL=https://<random>.trycloudflare.com npm run build  # в miniapp/
```

Для постоянного хостинга бэкенда используйте любой PaaS/VPS
(Dockerfile приложен); `web.py` слушает `0.0.0.0` и не зависит от бота.

| Метод | Путь | Параметры |
|---|---|---|
| GET | `/api/search` | `q`, `markets=ozon,yandex`, `initData` |
| GET | `/api/reviews` | `marketplace`, `ext_id`, `initData` |
| GET | `/api/compare` | `q`, `initData` |
| GET | `/api/budget` | `initData` |
| GET | `/health` | — |

Аутентификация: сервер проверяет подпись Telegram `initData`
(HMAC-SHA256, секрет — HMAC-SHA256 от токена бота) и берёт `user_id` из
апдейта — сессии общие с чатом. Для локальной разработки Mini App вне
Telegram (`SHOPPER_API_ALLOW_ANON=1`) подойдёт `user_id` из query; для
продакшена включите `SHOPPER_API_TOKEN` — Mini App шлёт его в заголовке
`X-API-Token` (переменная сборки `VITE_API_TOKEN`).

```bash
# пример (демо): токен бота из корневого .env
curl "http://127.0.0.1:8081/api/search?q=маска%20для%20сна&user_id=1"
curl "http://127.0.0.1:8081/api/compare?q=маска%20для%20сна&user_id=1"
```

## Ключи и ротация моделей

Скрипт `run_bot12.cmd` читает ключи из корневого `.env` портфолио:
`TG_TOKEN` → токен бота, `OPEN_ROUTER_KEY` → OpenRouter,
`OZON_KEY` → Ozon Seller API, `YANDEX_MARKET_KEY` → Partner API Яндекс
Маркета (два последних — API продавца, для каталога не используются; ключи
нужны только для своих товаров/заказов).

**Ротация :free-моделей (проверено на живом ключе 12.08.2026):** реестр в
`llm/gateway.py` калиброван живой пробой — рабочие модели стоят первыми в
цепочках, недоступные для этого аккаунта (guardrail-политика OpenRouter,
404) — в хвосте; `inclusionai/ling-3.0-flash:free` снят с бесплатного tier и
удалён. Роутер `openrouter/free` всегда последний — он сам выбирает
доступную бесплатную модель. Ответы запрашиваются через structured outputs
(`response_format: json_schema`), модели без поддержки получают тот же промпт
без response_format, а валидация pydantic-схемы отбракует кривой ответ и
переключит цепочку дальше.

```bash
pip install -r requirements.txt

```

На Windows: `run_bot12.cmd` сам читает ключи из корневого `.env`
(`TG_TOKEN`, `OPEN_ROUTER_KEY`, `OZON_KEY`, `YANDEX_MARKET_KEY`) и запускает

(см. `.env.example`): в коде их нет.

## Ограничения и планы

- Хранилище — SQLite; продакшн-таргет — PostgreSQL + Redis (схема спроектирована
  под миграцию без смены контрактов методов);
- клиент LLM создаётся на каждый запрос (оптимизация: пул сессий);
- фото в Mini App («Найти по фото») — в демо возвращает описание сценария
  «кроссовки»; реальное распознавание — через vision-модель при наличии ключа;
- HTTP-API для Mini App реализован (web.py: /api/search, /api/reviews,
  /api/compare, /api/budget; общие сессии с чатом); продакшн-развёртывание —
  HTTPS-хостинг Mini App и webhook вместо polling;
- реестр :free-моделей обновляется по мере ротации моделей OpenRouter.
